BREATHESAFE CAMPUS — FRONTEND AUDIT
Audit date: 2026-10-10
Scope: frontend/ (Next.js 16.4 App Router, React 19.3, Tailwind 4, TanStack Query 5)
Method: full code review; `tsc --noEmit`; `eslint src`; `next build`; live run in a
browser (desktop + 375px mobile, system dark mode), accessibility-tree and DOM checks,
network timing via Performance API. No code was changed.
Note: each dashboard load in demo mode writes a reading to the prod AQI table; this
audit's page loads added a few CAMPUS#delhi "poor" demo rows.

Legend:  [VERIFIED] = observed in the running app / tool output
         [REVIEW]   = found by code reading
Related: Product_Audit.txt, Backend_Audit.txt, Infra_Audit.txt (cross-referenced).

VERDICT: Builds and renders, the layout is responsive, and the visual language is
clean in light mode. But in dark mode (default on many Macs) key content is
invisible, the campus/location model is inconsistent (existing alerts don't show),
two sources of truth can disagree on AQI status, the "honest data" UI states don't
actually work, forms are inaccessible to screen readers, and the API client never
sends auth tokens — so it will break the moment the backend is secured.

CRITICAL

[F1] Dark mode makes the app unreadable                                  [VERIFIED]
  app/globals.css — create-next-app leftovers: under prefers-color-scheme: dark,
  body gets background #0a0a0a and color #ededed (unlayered CSS beats Tailwind's
  bg-gray-50 utility). Cards are bg-white, so every value inheriting body color
  (station, source, pollutant values, "Last updated", scenario select text) is
  #ededed on white; the page H1 (text-gray-900) sits on near-black. Measured:
  body bg rgb(10,10,10), value text rgb(237,237,237) inside white cards.
  `font-family: Arial` also overrides the Geist font loaded in layout.tsx.
  Fix: delete the :root dark override and body background/color/font rules (or
  build a real dark theme). Test with macOS dark mode before recording.

[F2] Campus/location model is inconsistent and fragile                   [VERIFIED]
  lib/useLocation.ts; called independently in app/page.tsx:17,
  components/AlertForm.tsx:31, app/alerts/page.tsx:117 AND inside every
  DecisionRecorder row (app/alerts/page.tsx:36).
  - Frontend campus = "delhi"; existing alerts live under "dtu-delhi" -> Alerts page
    shows "No alerts issued yet" although 2 alerts exist.
  - Each hook instance runs its own geolocation + Nominatim request (N alerts ->
    N+1 lookups). AlertForm's instance starts at the default and may submit an alert
    under a different campus than the dashboard shows.
  - Any unmapped city becomes a new campus key (CAMPUS#patna exists in prod).
  - Header reads "Delhi (default)" + "(Location access denied — showing Delhi)" —
    a campus product that never names the campus.
  - Browser blocks the custom "User-Agent" header (forbidden header) — Nominatim's
    usage policy (identify app, <=1 req/s) is not met; coordinates go to a third
    party, contradicting the About page privacy statement.
  Fix: fixed campus config (DEFAULT_CAMPUS/CAMPUS_DISPLAY_NAME already exist in
  lib/constants.ts and are unused) provided once via context; drop geolocation for
  the demo (removes the permission prompt from the video).

[F3] Two sources of truth for AQI status                                 [REVIEW]
  components/AqiHeroCard.tsx:20-27 computes status client-side with `<=` bounds;
  RecommendationCard shows the backend's status (integer-range bands that map
  fractional/invalid values to "Severe" — Backend_Audit B1). For AQI 100.4 the hero
  says "Moderate" while the recommendation says "Severe". Recommendation is also
  fetched separately from /recommendations, which reads "latest row in DynamoDB" —
  not necessarily the reading on screen (scenario changes, scheduler, other users).
  Status colours/labels are duplicated in 4 places (constants.ts, AqiHeroCard,
  TrendChart, About page table).
  Fix: render status from the backend only; fetch recommendation for the exact
  reading displayed (pass fetchedAt/scenario) or return both in one call; one
  status config module.

[F4] The "honest data" states don't work                                 [VERIFIED/REVIEW]
  - Stale banner (AqiHeroCard) can never fire: backend overwrites reading.timestamp
    with response time (Backend_Audit B5).
  - PRD states not implemented: "Cached (X min ago)", "Data unavailable — last
    reading at [time]". A backend 503 ("No AQI data available") is shown as the
    generic red "Failed to load air quality data" box.
  - Trend chart has NO demo label: 83 points, flat line at 268 with one spike —
    demo data presented as an observed trend (verified screenshot). Empty-state copy
    claims "fetches AQI readings every 15 minutes" (true only for campus "delhi").
  - Recommendation query errors are not rendered at all (app/page.tsx — no
    recQuery.isError branch); trend errors are silent.
  - "Last updated: Just now" is computed once at render; it doesn't tick.
  Fix: dedicated states for live / cached(age) / stale / unavailable / demo; demo
  badge on the trend card (or hide trends in demo); error states for every query.

[F5] API client ignores authentication                                   [REVIEW]
  lib/api.ts never attaches `Authorization: Bearer <token>`; createAlert and
  recordDecision are "protected" only by hiding buttons. Once the backend adds a
  Cognito authorizer (Infra_Audit C4), alert creation and decisions will 401.
  adminName is a free-text field pre-filled from the profile but editable (and
  defaults to "Campus Admin") — audit attribution can be spoofed from the UI.
  Fix: fetchApi reads tokens from auth context and sends the ID/access token;
  handle 401 by refreshing then retrying once; remove the adminName field (backend
  takes it from token claims).

[F6] Auth / session handling                                             [REVIEW]
  lib/auth.tsx, app/login/page.tsx
  - Access, ID and 30-day refresh tokens stored in localStorage (XSS = account
    takeover for 30 days). Acceptable for a hackathon; document it, and avoid any
    dangerouslySetInnerHTML / third-party scripts.
  - Open redirect: login uses `router.push(searchParams.get("redirect"))` unchecked
    (login/page.tsx:31) — /login?redirect=https://evil.example sends a freshly
    signed-in user off-site. Allow only paths starting with "/" and not "//".
  - If the profile fetch fails after sign-in, tokens are stored but user stays null
    -> redirect happens but the app shows "Sign In" again (silent failure).
  - UserNotConfirmedException on login isn't handled (no link to /verify); verify
    page has no "resend code"; no forgot-password flow.
  - signOut only clears local state — refresh token is not revoked (token
    revocation is enabled on the client; call RevokeToken).
  - Refresh runs on a 50-min setInterval with a captured token object; no refresh
    on 401 and no cross-tab sync (storage event).

[F7] Alert workflow gaps (the product's core "Act -> Record")            [REVIEW]
  - No recipient view: nothing shows alerts to students/staff (Product_Audit P0-5).
  - After "Send Alert" the user gets a banner, not the PRD's "Record your decision"
    prompt; decisions can only be recorded from the Alerts page.
  - No confirmation step before broadcasting to "All (Students, Staff & Parents)".
  - Message: no character limit/counter; whitespace-only custom decisions are
    blocked but values are not trimmed before save.
  - Alerts page: PRD's expandable evidence snapshot per row not implemented;
    audience shown raw ("students"); `aqi || "N/A"` hides a real AQI of 0; recorded
    decision shows no timestamp or who recorded it; no pagination/filtering.
  - Double-submit protection relies only on isPending (no idempotency key).

[F8] Accessibility (WCAG 2.1 AA)                                         [VERIFIED]
  - Form labels are not associated with inputs anywhere: signup 0/5 inputs
    labelled (verified via input.labels); same pattern in login, verify, AlertForm,
    DecisionRecorder; "Demo scenario" select has no accessible name.
  - No autocomplete attributes (email, current-password, new-password, name,
    one-time-code) — hurts password managers and mobile autofill.
  - Modal (AlertForm): no role="dialog"/aria-modal, no focus trap, no initial focus,
    no Escape to close, background scrolls; close button is "×" with no aria-label.
  - Disclosure "See evidence and rule": no aria-expanded/aria-controls.
  - Low contrast: disclaimer text-gray-400 on white (~2.5:1) — the key trust
    message; trend empty state text-gray-300 (~1.5:1); chart axis labels.
  - Status conveyed by colour only in the chart (dots/line); legend shows only
    Good/Satisfactory/Moderate/Poor (TrendChart.tsx:59 slice(0,4)) — omits Very Poor
    and Severe, the categories that matter most.
  - No skip link; nav links lack aria-current; logo is an emoji; live-pulse
    animation ignores prefers-reduced-motion; chart SVG has no title/desc.

[F9] Trend chart rendering                                               [VERIFIED]
  components/TrendChart.tsx
  - preserveAspectRatio="none" (line 172) stretches the 140x190 viewBox to the card:
    text and point circles are distorted; axis labels use fontSize 2.5–3 user units
    and are illegible on desktop and mobile (verified screenshots).
  - X-axis shows time only — 48h/7d views have ambiguous labels; no tooltips/values.
  - Hard-coded gradient id "trendFill" (collides if two charts render).
  - No dataMode on points -> can't distinguish demo from measured (F4).
  Fix: fixed aspect ratio (or measure width), readable 11–12px labels, date+time
  ticks for >24h, full 6-band legend, demo badge.

[F10] Data fetching & performance                                        [VERIFIED]
  - Waterfall: /recommendations waits for /aqi (app/page.tsx:28). Measured
    aqi 1.84s -> recommendation 1.35s => ~3.2s before the recommendation appears
    (PRD target: status + recommendation in under 3s). Fetch in parallel or return
    both from one endpoint.
  - Global refetchInterval 60s + retry 2 (Providers.tsx:14-15) applies to every
    query incl. alerts and trends; in demo mode each /aqi poll writes a DynamoDB row
    (prod trend shows one row per minute overnight). Set per-query intervals; don't
    retry 4xx.
  - Query keys inconsistent: recommendation key includes scenario (backend ignores
    it) but not city; aqi key includes city.
  - No request timeout/AbortController in fetchApi; backend error body shapes vary,
    so error messages are mostly generic.
  - API base URL hard-coded as a fallback in two files (lib/api.ts, lib/auth.tsx);
    a missing env var silently points any build at prod.

[F11] Demo controls exposed to every user                                [VERIFIED]
  "Demo scenario" dropdown is always visible (even in live mode) and changing it
  writes a reading that every other viewer then sees. Show only when the backend
  reports dataMode "demo" (or behind ?demo=1), and label it as a presenter control.

[F12] Content accuracy
  - About page action table text differs from the engine's actual actions (e.g.
    "Avoid outdoor activities. Issue campus advisory." vs backend "Avoid prolonged
    outdoor activities. Issue campus advisory to all stakeholders.") — the
    transparency page doesn't match what the engine says. Render from shared config.
  - About page privacy statement contradicts geolocation + Nominatim + Cognito PII.
  - About "AWS Architecture" omits Cognito, EventBridge, Bedrock.
  - Pollutant keys rendered via toUpperCase(): "PM25" instead of "PM2.5"; no units
    (µg/m³; mg/m³ for CO) on an "evidence" card.

[F13] Resilience & routing
  - No app/error.tsx / global-error.tsx — any render error white-screens the app.
  - No loading.tsx; default unstyled Next 404 page.
  - Every route shares one <title> ("BreatheSafe Campus — Air Quality Action
    Engine"); client-component pages can't export metadata — add per-route
    layout.tsx metadata.

[F14] Lint failures (3)                                                 [VERIFIED]
  See HEALTH CHECK. AqiHeroCard: compute "now" in state/effect or a ticking hook.
  auth.tsx / useLocation.ts: move synchronous setState out of effects (lazy initial
  state / derive). A CI lint step would currently fail.

[F15] Next.js configuration
  cacheComponents + partialPrefetching are enabled, but every page except About is a
  "use client" component that fetches client-side — no benefit, extra complexity.
  Either use server components for the static shell or drop the flags. Check that
  the intended hosting (static export to S3/CloudFront or Amplify) supports them.

[F16] Security headers / hosting (once deployed)
  No CSP, X-Content-Type-Options, Referrer-Policy, frame-ancestors, Permissions-
  Policy (geolocation) — add via next.config headers() or CloudFront response
  headers policy. Important given tokens live in localStorage.

[F17] Code organisation
  - lib/types.ts duplicates backend/shared types by hand (drift risk).
  - No custom hooks layer (ARCHITECTURE.md lists useAqi/useRecommendation/useAlerts);
    DecisionRecorder lives inside the alerts page file.
  - No tests (component or e2e). A single Playwright happy-path (dashboard -> sign in
    -> issue alert -> record decision) would protect the demo flow.
  - Leftovers: public/{file,globe,next,vercel,window}.svg, create-next-app README,
    favicon likely the template default (verify); AGENTS.md is auto-generated by
    next dev.

CRITICAL — fix before recording / judging
======================================================================

[C1] Bedrock fails on EVERY request — AI Insight never appears          [VERIFIED]
  Evidence: 28x "Bedrock narrative failed ... ValidationException: Operation not
  allowed" in /aws/lambda/breathesafe-recommendation-prod (last 24h).
  get-foundation-model-availability -> authorizationStatus NOT_AUTHORIZED,
  agreementAvailability NOT_AVAILABLE; get-use-case-for-model-access -> "You have not
  filled out the request form". Error is caught, so it fails silently.
  CORRECTION to earlier audit: claude-3-haiku-20240307 is still ACTIVE in ap-south-1;
  model EOL is NOT the cause.
  Fix:
   1. (Owner action) Bedrock console -> Model catalog -> Anthropic model -> submit
      the Anthropic first-time-use / use-case form. Then run one prompt in the
      Bedrock playground (as an admin principal) so the Marketplace subscription is
      created — the Lambda role has no aws-marketplace permissions to do it itself.
   2. Consider moving to a current model via India geo inference profile, e.g.
      in.anthropic.claude-haiku-4-5-20251001-v1:0 (keeps data in India). IAM must then
      allow the inference-profile ARN AND the underlying foundation-model ARNs.
   3. Remove hard-coded region in BedrockRuntimeClient; add a 5–8s timeout; cache
      the narrative per reading (currently invoked on every request / 60s refetch).
   4. Log a WARN metric when narrative generation fails so this is visible.

[C2] Audit trail can be permanently deleted                             [VERIFIED]
  AlertsDecisionsTable (the product's core asset) and AQIReadingsTable: no
  DeletionPolicy/UpdateReplacePolicy, DeletionProtectionEnabled=false, PITR DISABLED,
  0 backups. Explicit TableName means any replacement-requiring change fails the
  stack update. Stack termination protection is OFF.
  Fix: DeletionPolicy: Retain + UpdateReplacePolicy: Retain + DeletionProtectionEnabled:
  true on both tables; PointInTimeRecoverySpecification on alerts table; enable stack
  termination protection.

[C3] Deploying "dev" would destroy prod data                            [IaC]
  samconfig.toml fixes stack_name = "breathesafe-campus". `sam deploy
  --parameter-overrides Stage=dev` renames tables inside the PROD stack -> creates new
  tables and deletes the old ones (no Retain).
  Fix: add a [dev.deploy.parameters] section with stack_name breathesafe-campus-dev;
  rehearse demos there, not in prod.

[C4] No abuse / cost protection on a public API                         [VERIFIED]
  - Stage has no throttling (account default 10,000 rps / 5,000 burst), no usage plan,
    no WAF, no authorizers.
  - POST /alerts and PATCH /decision are unauthenticated; /alerts is publicly readable
    (includes admin names).
  - In demo mode every GET /aqi writes a DynamoDB row; `campus` accepts any string
    (CAMPUS#patna already exists).
  - No AWS Budget or billing alarm.
  Fix: stage MethodSettings throttling (e.g. 20 rps / burst 40); Cognito authorizer
  on POST /alerts and PATCH /decision (adminName from token claims); campus
  allowlist; GET must not write in demo mode; AWS Budget with $5/$10 email alerts.

[C5] Lambda timeouts exceed API Gateway's 29s limit                     [VERIFIED]
  All functions 30s, recommendation 60s. Client gets 504 while Lambda keeps running.
  Fix: Timeout <= 25s; bound Bedrock call with AbortSignal/timeout.

[C6] Deprecated runtime nodejs20.x                                      [VERIFIED]
  Node.js 20 reached EOL 2026-04-30 (no security patches). Function updates still
  succeed today (deploy on 2026-10-10 worked), but AWS block dates are approaching.
  Fix: Globals Runtime: nodejs22.x (or nodejs24.x); rebuild + smoke test all routes.

[C7] Account concurrency quota is 10                                    [VERIFIED]
  All 5 functions share 10 concurrent executions. A burst (judges + demo + scheduler,
  or a simple loop script) -> 429/502s. Observed max is 1 today, so low risk for a
  recorded demo, but it's a hard ceiling.
  Fix: request increase via Service Quotas ("Concurrent executions", Lambda,
  ap-south-1) — free, may take time. Do NOT add reserved concurrency until raised
  (it would eat into the 10).

[C8] Working as ROOT; teammates have no usable IAM access              [VERIFIED]
  CLI session is arn:...:root. Teammate IAM users have console access but no MFA and
  no permissions (only IAMUserChangePassword) -> encourages sharing root.
  No account password policy.
  Fix: create an admin IAM group (or IAM Identity Center) for the team, require MFA,
  set a password policy, use that identity for `aws login`/SAM. Keep root for
  break-glass only.

HIGH — reliability, security, and a credible repo
======================================================================

[H1] Zero observability                                                 [VERIFIED]
  No alarms, no dashboards, X-Ray off, no API access logs, no API GW CloudWatch
  role, log groups "Never expire" and not managed by the stack, no CloudTrail trail.
  Fix: AWS::Logs::LogGroup per function (14-day retention); alarms on API 5XXError,
  Lambda Errors/Throttles, Bedrock-failure metric -> SNS email; Tracing: Active on
  functions + API (X-Ray service map is good demo footage); API access logging;
  one CloudTrail management-events trail.
  (Source maps are already enabled — NODE_OPTIONS is set by SAM esbuild; stack traces
  show handler.ts lines. Earlier audit note on this is withdrawn.)

[H2] API-Gateway-generated errors lack CORS headers                     [VERIFIED]
  403 MissingAuthenticationToken returned without Access-Control-* headers. Once an
  authorizer is added, 401s will surface in the browser as opaque CORS failures.
  Fix: GatewayResponses DEFAULT_4XX / DEFAULT_5XX with CORS headers in the SAM Api.

[H3] API keys stored in plaintext                                       [VERIFIED]
  CpcbApiKey and OpenAqApiKey are visible in CloudFormation stack parameters and as
  plain Lambda env vars (CPCB_API_KEY, OPENAQ_API_KEY). Parameters lack NoEcho.
  DO NOT show the Lambda Configuration -> Environment tab or stack Parameters tab in
  the demo video.
  Fix: SSM Parameter Store SecureString (read at cold start, cached) or Secrets
  Manager; at minimum NoEcho: true. Rotate both keys after the hackathon (repo will
  be public; keys are not in git, but treat them as exposed to anyone with console
  access, including shared root).
  Note: samconfig parameter_overrides only sets DataMode/Stage — confirm a plain
  `sam deploy` keeps the key values (risk of silently resetting to 'none').

[H4] IAM broader than needed                                            [VERIFIED]
  - FetchAQI and Alerts use DynamoDBCrudPolicy (includes DeleteItem, Scan, BatchWrite).
  - Auth role grants cognito-idp:AdminGetUser/AdminUpdateUserAttributes — unused.
  - Recommendation role: fine (read-only + one Bedrock ARN).
  Fix: explicit actions — FetchAQI: PutItem, Query; Alerts: PutItem, Query, UpdateItem
  (+ Query on readings); drop unused Cognito admin permissions.

[H5] Cognito gaps                                                       [VERIFIED]
  - App client Read/WriteAttributes unrestricted -> any user can set custom:role on
    themselves (UpdateUserAttributes with own access token).
  - Email via COGNITO_DEFAULT (~50 emails/day account cap) -> sign-ups can stall.
  - MFA OFF; DeletionProtection INACTIVE; no DeletionPolicy on UserPool.
  - No forgot-password route in the auth Lambda/frontend (recovery is configured in
    the pool but unreachable from the app).
  - USER_PASSWORD_AUTH sends passwords through our Lambda (SRP preferred).
  - SignUp errors reveal whether an email is registered.
  Fix: restrict WriteAttributes (exclude custom:role), DeletionProtection ACTIVE +
  Retain, add forgot/confirm-forgot routes, SES for email post-hackathon.

[H6] Input handling returns 500s                                        [VERIFIED]
  Malformed JSON -> 500 ("SyntaxError ... at handleCreateAlert"). Missing alert on
  PATCH -> 500. No length cap on message/adminName (DynamoDB 400 KB item limit).
  Fix: 400 on bad JSON, 404 on missing alert, field length limits, API GW request
  validators/models.

[H7] TTL (48h) vs Trends window (up to 7d)                              [VERIFIED]
  Readings expire after 48h but /trends accepts hours up to 168 and UI offers "7d".
  Fix: align TTL with the longest window, or remove 48h/7d options.

[H8] Scheduled fetch                                                    [VERIFIED]
  Healthy (0 failures), but: no on-failure destination/DLQ or alarm; in demo mode it
  writes a fixed "poor" reading to CAMPUS#delhi every 15 min, overwriting the
  presenter's chosen scenario; campus key differs from frontend/alerts (dtu-delhi).
  Fix: skip writes in demo mode; align campus key; add OnFailure destination + alarm.
